**How this page is laid out.** §1 and §2 hold what is waiting on the operator or on the outside world.
§3 holds the open rows, grouped by **product area**, and inside each area by **functionality**. §4
(engineering platform) and §5 (docs and board hygiene) are the two non-product areas. §6 is the standing
refusals, grouped the same way. §7 maps duplicate names. **Find a row by its id or name, not by section
number** — rows moved between sections in this consolidation, and older docs cite the old sections.

**Row tags (binding, 2026-10-19).** Every ranked row in §3–§5 ends its first line with
`[items: <id>, <id> · kind: <kind> · hold: <hold>]`. Each `<id>` is a Product Map Item id (`<kind>.<name>`, a file
`product-map/<kind>/<name>.toon`) — the hub(s) the work belongs to; a cross-cutting row uses
`layer.platform` (backend) or `layer.product` (UI / whole product). `kind` is one of `feature` (new or
missing capability), `defect` (something built behaves wrongly — never call it an "Issue", see
`GLOSSARY.md`) or `chore` (measurement, live run, validation, upkeep). `hold`, only on a row that is not
startable now, is `operator` (waits on an operator call), `external` (waits on the outside world: an
upstream release, a real account, a real user) or `demand` (waits for a customer or consumer to ask).
`kind` and `hold` may be omitted. Each hub's
`index.md` shows its rows under **Open work**, generated from this page by `tools/render-product-docs.mjs`
— this page stays the only list. Checked by `tools/check-backlog-items.mjs`.
