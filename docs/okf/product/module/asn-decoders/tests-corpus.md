# Golden corpus (Phase 0 — REDESIGN.md §6)

> Moved verbatim from `providers/asn-parser/corpus/README.md` (2026-11-19, `INFO-RESTRUCTURE-1` W3), which is now a pointer here.

Captured output of **today's legacy decoder** (`asn2.ASN1Reader` + `transformer2.Transformer`)
over every `config/` + `data/` pairing that works. This is the only objective definition of
"current behaviour" — **including its bugs**. The rewrite (asn-core/asn-schema/asn-transform)
is validated against these files; every intentional difference must appear in a written
deviation report, never silently.

## The committed complement

This corpus never enters git. The synthetic subset that DOES — hand-written grammars + hex-text BER + expected
records, run by `SyntheticCorpusTest` on every build — lives in `../corpus-synthetic/` (DATA-GOV-1, 2026-09-06).

## Regenerate

```powershell
cd asn-decoders
.\run-golden.ps1
```

One JVM per case (the legacy transformer has static config and its cartesian join can OOM);
output is deterministic — a re-run is byte-identical.

## Layout

- `<case>/<datafile>.records.jsonl` — one decoded record map per line, legacy key order.
- `<case>/<datafile>.rows.jsonl` — flattened transform rows (`{record, type, row}`), where
  a usable legacy tx config exists.
- `<case>/report.json` — the config tuple (grammar / root tag / skipLines / framing / tx)
  plus per-file counters: `records` (full file), `capturedRecords`, `emptyRecords`, `rows`,
  `errors`.
- `SUMMARY.json` — all case reports.

**Capture is capped at the first 100 records per file** (CCN/OCC records are ~25 KB each;
uncapped the corpus is ~350 MB). Whole files are still decoded, so `records`/`readerRecCount`
give full-file structural parity; content parity uses the captured head.

## Parity

`PARITY.md` + `<case>/parity.json` are generated by `ParityCheck` (asn-golden) and
compare the NEW stack against this corpus — see `asn-decoders/README.md` for the
current parity status and known deviations.

## Caveats

- `records.jsonl` values come from the legacy decoders with all their known bugs
  (REDESIGN.md §3 lists which are contractual and which are not).
- One skipped/empty record per OCC/CCN file (`emptyRecords: 1`) is legacy behaviour.
- Rows for aftel KABUL…543 differ between capped (738) and uncapped (1107) runs only
  because of the 100-record cap.
- Samples contain real subscriber identifiers (MSISDN/IMSI) — same exposure as the
  committed `data/` samples; treat the repo as sensitive, don't publish.

## Synthetic corpus (DATA-GOV-1 — the committed CI complement)

> Moved verbatim from `providers/asn-parser/corpus-synthetic/README.md` (2026-11-19, `INFO-RESTRUCTURE-1` W3), which is now a pointer here.


The real carrier corpus (`corpus/`, `config/`, `data/`) is operator data: it never enters git and its parity
harness (`ParityCheckTest`, `RealGrammarsTest`) is opt-in (`-Dasn.corpus.tests=true`) wherever the encrypted
archive is provisioned. **This directory is the small synthetic subset the DATA-GOV-1 decision (2026-09-06) asked
for**: hand-built BER that exercises the decoder's structural machinery on every CI run, with no subscriber
identifier, no carrier file name and no vendor grammar in it.

It is a **complement, not a replacement** — every parity defect so far came from real files. What it pins is
that the new stack still decodes, frames, binds and maps what it did yesterday.

### Layout

One directory per case:

| File | Meaning |
|---|---|
| `grammar.asn` | a small ASN.1 module written for the case (not a vendor grammar) |
| `case.json` | `root` type, `fileHeaderLength`, `recordHeaderLength` (null = none), `padding` bytes |
| `data.hex` | the BER file as hex TEXT — `#` comments and whitespace are ignored. Text, so the repo-wide `*.ber` ban stays intact and the bytes are reviewable in a diff |
| `expected.jsonl` | one `RecordMapper` map per decoded record, JSON, in file order |

### Cases

| Case | Exercises |
|---|---|
| `backtoback` | back-to-back records, no framing; `[APPLICATION n]` root, OPTIONAL absent/present, SEQUENCE OF, CHOICE, multi-byte lengths and INTEGER values |
| `repeated_child` | SEQUENCE OF SEQUENCE lists (identity {type,value} and service-data {group,up,down}); OPTIONAL list absent, empty list — the Parsing D9 `derive` fixtures |
| `repeated_child_nested` | a list whose elements each carry a NESTED list (usage → charges), one element with the nested list absent — lets a `derive` declared on a child segment yield real values |
| `huawei_framed` | the vendor file shape without the vendor: a 50-byte file header, a 4-byte header before every record (`skipOnly`), 0x00 trailing padding; BOOLEAN, OCTET STRING, nested SEQUENCE |

### Running / regenerating

`SyntheticCorpusTest` (asn-golden) runs in the normal reactor — no flag. To regenerate `expected.jsonl` after an
INTENTIONAL decoder change:

```
mvn -o -q test -pl providers/asn-parser/asn-decoders/asn-golden -am -Dtest=SyntheticCorpusTest -Dasn.synthetic.write=true
```

then review the diff — a changed expectation is a behaviour change and needs a reason in the commit.

### Adding a case

Keep it synthetic: invent the grammar, invent the values. If you need a vendor grammar's shape, mimic the shape
(tags, framing, nesting), never copy the grammar or a captured record.
