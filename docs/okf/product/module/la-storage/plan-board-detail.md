### LA-ENTITY-KEY-NEW-CASE-PAIRS-1

- `LA-ENTITY-KEY-NEW-CASE-PAIRS-1` — **the SQL entity key and the Java key still differ for about 55 letters per case rule.** Unicode case pairs newer than DuckDB 2.0.0.0's case tables (`ɤ` / U+A7CB, `ƛ` / U+A7DC, U+1C89 / U+1C8A, U+A7CC–A7DB, Garay U+10D50–10D75) are left as written by DuckDB `upper` / `lower` but folded by Java `Locale.ROOT`, so a typed key spelt with one of them can miss its other spelling on the Dataset path. Found 2026-11-16 by the exhaustive probe of the `LA-INDEX-SPELLINGS-1` review (3,568,112 checks, 330 mismatches, 55 per rule among cased letters). Safe meanwhile: the Dataset match keeps the raw equality and the index fold keeps the value, so no read or four-eyes count falls below its exact match. Fix: add these pairs to `EntityKeySql`'s fold table (read from the JDK, as the full mappings are) and to `entity-normaliser-parity.fixture.json`. → `okf/product/module/la-storage/architecture-la-storage.md`
