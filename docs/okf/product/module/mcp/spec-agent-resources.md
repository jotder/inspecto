# Agent reference resources

Widening plan `docs/superpower/2026-11-25-agent-kit-ak2-widening-plan.md` § W5. Goal: an agent reads a kind's keys,
types and an example **before** it drafts a `propose_change`, and reads what a refusal's code means **after** one,
instead of learning the shape from 422s. This is the serving half; the two generators are their own rows
(`COMPONENT-REFERENCE-GENERATED-1`, `ERROR-CATALOGUE-1`).

## The resources

| URI | mimeType | Served from (classpath of `inspecto-mcp.jar`) | Generated by |
|---|---|---|---|
| `inspecto://shapes/{kind}` — one per `propose_change` kind (12) and per other shaped component kind (11) | `application/json` | `META-INF/inspecto/mcp/api/component-shapes/<kind>.json` | `ComponentShapesTest` → `docs/api/component-shapes/<kind>.json` |
| `inspecto://errors` | `application/json` | `META-INF/inspecto/mcp/api/errors-v1.json` | `node tools/render-error-catalogue.mjs` → `docs/api/errors-v1.json` |

Alongside the three that were there: `inspecto://glossary`, `inspecto://catalog`, `inspecto://modules`
([spec-mcp.md](spec-mcp.md)).

- **One list, derived.** `McpTools.RESOURCES` adds one `inspecto://shapes/<kind>` per kind of `McpTools.shapeKinds()`
  (sorted): every key of `McpTools.CHANGE_ROUTES`, so a new `propose_change` kind lists its shape resource without a
  second edit, and every kind of `McpTools.COMPONENT_SHAPE_KINDS` — the component kinds `propose_change` does not
  offer but that have a generated shape (`dataset`, `reconciliation`, `kpi`, `schema`, `mapping`, `runbook` and the
  five model kinds; COMPONENT-REFERENCE-MORE-KINDS-1, 2026-11-27). **They are served deliberately**: an agent drafts
  a Dataset, a Reconciliation or a KPI for a person who saves it through `/components/<type>`, and reads an existing
  one's keys. Their file names the component type, says `proposeChange: false` and lists the component routes; the
  resource's description says it is not a `propose_change` kind. A component kind with no shape is named, with why,
  in `ComponentShapesTest.UNSHAPED`.
- **Verbatim, banner kept.** `resources/read` returns the packaged file's bytes unchanged (clipped at
  `McpRoutes.MAX_RESULT`, 256 KiB; the largest shape is ~9 KB, the catalogue ~41 KB). Each file's own
  `generatedBy` field (and the catalogue's `$comment`) is that banner: an agent and a reviewer both see the file is
  generated and how to regenerate it.
- **Packaged at build time.** `features/inspecto-mcp/pom.xml` copies `docs/api/component-shapes/*.json` and
  `docs/api/errors-v1.json` into the jar under `META-INF/inspecto/mcp/`, as it copies `docs/GLOSSARY.md`. The jar
  therefore carries the reference of the commit it was built from. `inspecto/package.ps1` refuses a bundle whose
  MCP jar lacks the catalogue or every shape file.
- **No replay, no Space.** These are product reference, not Space data: they are read from the classpath, not by
  replaying a route, so they need no capability beyond reaching the endpoint, and each read still leaves the
  `mcp.resource.read` AUDIT row. A missing file answers the resource error `<name> is not packaged in this build`.
- **Discovery.** The endpoint's `instructions` tell the agent to read `inspecto://shapes/{kind}` before drafting a
  `propose_change` and `inspecto://errors` on a refusal, and (2026-11-27, `AGENT-ANSWERS-WITHOUT-SERVER-1`) to ask
  the server, through `preview_config` and `dry_run_pipeline`, for types, casts, parsing and what a draft does to
  rows instead of working it out; `McpInstructionsTest` checks that every tool the text names exists. The Pipeline
  shape's example is a graph the save lowers (`ComponentShapesTest.thePipelineExampleIsAGraphTheSaveLowers`):
  agents copy it.

## The skills

`safe-config-change` (the Draft step and the 422 row; the Decision Rule, Notification Rule, Channel and
`requirement-kpi` content now points at the shape instead of listing keys), `author-pipeline`, `add-expectations`,
`author-alert-rules`, `build-dashboard` and `work-cases` (Entity Lists) read the kind's shape resource before they
draft. Two pieces of prose stay, because the generated shape types the field without its values: the Decision Rule
`when` condition tree and its operators (`when` is only an object), and a Notification Channel's `kind`, EMAIL or
WEBHOOK (only a string).

## Tests

- `ControlApiMcpTest.everyProposeKindHasAShapeResource` — **the guard**: for every `shapeKinds()` kind, a
  `inspecto://shapes/<kind>` resource exists and its classpath file is packaged. A kind added without regenerating
  the shape reference fails here (as well as in `ComponentShapesTest`).
- `ControlApiMcpTest.theShapeAndErrorResourcesAreServed` — over real HTTP: `resources/list` names `inspecto://errors`
  and every shape; `resources/read` answers each kind with its own `kind`, its operations and the `generatedBy`
  banner, and the catalogue with its banner and codes.
