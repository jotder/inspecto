# Telecom industry pack — brochure

> **Link Analysis that speaks telecom — lines, identities and handsets linked by calls, messages, forwarding and shared devices.**

*Audience: customers, presales and sales. Product Map Item `solution-pack.industry-telecom` · status **ga**. Prices are not published here.*

## Who it is for

Telecom fraud and security analysts using Link Analysis.

## The problems it solves

- A generic graph does not know what an MSISDN, IMSI or IMEI is, or which identifiers must be masked.
- Starting an investigation from one phone number needs sensible defaults.

## What is included

- Telecom Entity Types (subscriber, MSISDN, IMSI, IMEI, handset, cell) with normalisers and masking on personal identifiers.
- Telecom link kinds and terms.
- Four pattern packs: forwarding relay, forwarding chain, payment ring, subscription ring.
- A domain profile with "investigate a number" defaults.
- Paired Space templates: [Telecom fraud](../../solution-pack/telco-fraud/brochure.md) and [Link Analysis showcase](../../solution-pack/la-showcase/brochure.md).

## How it fits with the Editions

Included in every Edition, [Basic](../../edition/basic/brochure.md) upwards (it is part of the Link Analysis base). The separate ASN.1 CDR decoders ([Telecom industry pack Add-on](../../addon/telecomIndustryPack/index.md)) are [Standard](../../edition/standard/brochure.md) and up. Licensed by contract.

## How it works

Select the Telecom domain profile for a Space; Link Analysis then labels, normalises and masks telecom identifiers and offers the telecom pattern packs and investigation defaults.

## Next step

See it in the Link Analysis showcase, then apply it to your own CDR link Dataset.
