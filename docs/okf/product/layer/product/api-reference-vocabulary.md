# Vocabulary

The 251 words Inspecto uses, each with the first sentence of its definition. One word names one thing, and
the console, the API and this Handbook use the same word.

## Rules of this vocabulary (non-negotiable)

- **Consequence provider** — The SPI through which an optional module registers its **Consequences** (§4) in the **Consequence registry**.
- **Host boot hook** — The SPI through which an optional module installs its host-wide seams once the host has its Spaces, so its routes stay drivable without a running host.

## Tenancy

- **Space** — A fully isolated project environment in one Inspecto installation.
- **Closed Space** — A **Space** that only the people it **admits** may use: its creator, a holder of `canAdminister`, and a holder of a **Role** its own role table defines (`space.toon` `admission: closed`, with `created_by`).
- **Pod** — One running Inspecto process in a horizontally-scaled Advanced deployment.
- **Config** — The JSON specification of any Component, stored in **TOON** format.
- **Space Template** — A reusable blueprint bundle of Components (Collectors, Pipelines, Schemas, Datasets, Widgets, Dashboards, Rules, optional seed data) that instantiates a new **Space**.
- **Metadata Bundle** — A selective, artifact-level export file (**configuration only, never data rows**) for moving definitions between Inspecto instances (staging → production): dataset metadata, Widgets, Dashboards, saved Link-Analysis/Geo-Map views, Pipelines, and their registry pieces (grammars/schemas/transforms/sinks/ connections, secrets masked).
- **Bundle v2 / self-describing subgraph** — A Metadata Bundle that carries its own lineage and origin so the target can validate it without re-deriving refs: each item's outgoing **refs** (marked `included` if the referent travels, `external` if it must already exist), its **provenance**, and the bundle's top-level **requires** (the deduped external refs — its contract with the target).

## Personas & Surfaces

- **Lens** — A persona-scoped view of the one operator console: **Business** (consume data, investigate provenance/lineage, raise Requirements) · **Builder** (author in Workbench + Studio) · **Ops** (built-in operational features).
- **Demo User** — A **sign-in identity for an offline demo build only** (`inspecto-demo-auth`, never an edition): a named entry in a Space's `config/demo-users.toon` that holds one or more **Roles** of that Space's role table, chosen from the sign-in page's picker with no password.
- **Role** — An **assigned authorization** (security-module editions): a named grant set held by a user (e.g. Business User, Pipeline Developer, Operations/Support, Power User, Admin, Super User).
- **Capability** — One named authorization question the UI gates on.
- **Inbound Investigation grant** — The integration **Capability**: opening a Link Analysis **Investigation** from an external system's record (`POST /inv/inbound/investigations`) and nothing else; the caller reads the Investigations it leads through the Investigation's own member rule.
- **Access Catalog** — The canonical tree of gateable surface: menu groups → panes → functionalities (action nodes, each bound to exactly one Capability).
- **Access Profile** — One subject's sparse **Grant** map over the Access Catalog; `subjectType` is `lens` today (Builder/Ops/Business visibility shaping) and `role` under RBAC — same document, same editor, only the subject and the enforcement change.
- **Grant** — An Access Profile entry `nodeId → allow | deny`; absent = inherit from the nearest explicit ancestor, root default allow.
- **Share** — One entry of a registry component's optional sharing envelope (`shares: [{subjectType: role|user, subjectId, access: view|edit}]`, plus `owner`): an intra-Space, per-subject access grant on that one component.
- **Access Policy** — An authorable **allow/deny statement over Attributes** (Advanced policy engine): `{name, effect: allow|deny, target: {actions?, resourceKinds?}, when: <condition>}` in a per-space `access-policies.toon` (`GET/PUT /access/policies`); the `when` condition is the shared `Conditions` grammar over `subject.* / resource.* / env.*`.
- **Safety Policy** — What a Space's **runs may touch**: filesystem roots, network hosts, Connector schemes, DuckDB extensions, output formats, caps and progress-state advances.
- **Attribute** — A named **subject / resource / environment fact** an Access Policy conditions on: subject = `id`, `capabilities`, `dataScopes`, plus IdP claims allowlisted in `roles.toon` `identity.attributeClaims` (never the raw token); resource = the component/object envelope (`kind`, `space`, `owner`, `tags`, …); environment = `action` (read/write/operate), `route`.
- **Workbench** — The Builder surface for acquisition + processing authoring: Connections, Collectors, and Pipelines.
- **Studio** — The Builder surface for BI authoring: Datasets, Widgets, Dashboards, plus the Link Analysis and Geo Map Analysis studios.
- **Requirement** — A Business-authored request for a deliverable — **KPI | Report | Reconciliation | Rule** — with lifecycle `submitted → accepted | rejected → delivered` (Business submits; Builder triages the intake queue and decides; delivery is recorded against the requirement), linkable to the Component(s) that satisfy it.
- **Handbook** — The user's view of the documentation: chapters in lifecycle order (Understand → Build → Ship → Manage → Develop) for each track — console builder, partner developer, operator — rendered from hub pages by one navigation manifest and served in the console at `/help` and as a static site.
- **Learning Path** — An ordered set of Handbook tutorials, Labs, videos and self-checks for one track, ending each lifecycle stage with a self-check.
- **Lab** — A hands-on exercise: a `lab-*` Space Template that seeds a starting state, plus a checker that reads the learner's result through the API.

## Connectivity & Ingestion

- **Connection** — Named endpoint + credentials for reaching a remote system (SFTP/FTP/FTPS, a database, cloud storage).
- **Collector** — A configured collection task bound to one Connection: what to collect (paths/queries), how often, filename patterns, dedup policy.
- **Feed** — A Collector bound to a recurring inbound delivery cadence.
- **Onboard / Onboarding** — The **guided end-to-end creation of a data origin** (a Stream or a Reference, §3): Catalog ▸ *Onboard Stream / Onboard Reference* opens a stage rail (Collection → Parsing → Schema/Keys → [Enrichment] → Go-live) that authors the real Stage-1 pipeline config server-side; a draft is just an `active: false` pipeline.
- **Add data** — The Inspecto LA entry point to **Onboard a file** as a Stream or a Reference: the button says *Add data*, the screen title says *Onboard a file*, so "Onboard" stays the one verb.
- **Arrival** — One file a Dataset's Pipeline took: an upload (*Add data*, *Add a file*) or a file a foreign process put in its inbox (*from a system*).
- **Data status** — The one line that says, for a Dataset, when data last **arrived** (*Received*), the period its kept data **covers** (*Data as of* is the end of that period), and whether the **graph** includes it (*up to date*, or *N files behind*) — said only when known.
- **Replace the period it covers** — What an added file may do to an import Dataset with a *When* column: its rows are added and the older rows on the days it covers are removed; every other day stays.
- **Link index** — Link Analysis' prebuilt store of a Dataset's links, built from its files so a graph reads fast; built in the import run, or by the Space's `la.index.build` Job (Standard and above).
- **Consignment** — A set of one or more files ingested and processed together as one unit of work.
- **File** — A single collected file.

## Schema & Catalog

- **Schema** — The column-and-type structure of one relation: field names, **Attribute Types**, and validation.
- **Mapping** — The reusable field map applied by a *map* Step: rows of *target column ← source expression (+ kind: direct/expr)*.
- **Field** — One column in a Schema: name, selector (how to locate it in the raw file), Attribute Type, and optional rules.
- **Attribute Type** — The data type of a Field: `string`, `integer`, `decimal`, `boolean`, `date`, `datetime`, `time`, `currency`, `enum`, `array`, `object`.
- **Catalog** — The library/index of all Schemas (and Datasets) in a Space, with version history and usage.
- **Stream** — A named external **event / fact data origin** as seen in the **Catalog**: one business sub-system (mediation, switch, VAS, …) whose files are **time-series, append-only, non-editable** records (XDR-style), meant to be summarized/rolled up.
- **Reference** — A named external **dimension data origin**, the slow-changing counterpart to a **Stream**: lookup / master data (rate plans, cell sites, customer master).
- **Segment** — **One record kind a plugin ingester emits**, with its own flat output Schema.
- **Field Classification** — The label on a Schema field, a Dataset column or a Step's output column that says what the column holds (`MSISDN`, `ACCOUNT`, `PII`, `INTERNAL`, …).

## Rules (three distinct engines — never bare "Rule")

- **Expectation** — A **data-quality** rule that validates records against a Schema (non-null, range, regex, referential).
- **Alert Rule** — Watches an observability **Metric** — or, since BI-5, a BI **Measure** over a Dataset — against a threshold and fires an **Alert** when crossed.
- **Decision Rule** — A **business-logic / routing** rule that transforms or routes records (e.g. send event-type X to sink Y).
- **Rule Template** — A **saved parameterized query** authored from the data-table Pro Max "save as rule" action: a projection + condition group (or hand-edited SQL override) plus `:fieldValue` binds, so a job can re-run it with different values.
- **Anomaly Model** — The authored **Type** (Component kind `anomaly-model`) that scores each entity against its own history and its **Peer Group**: a set of **Features**, a baseline window, seasonality and thresholds.
- **Anomaly Score** — The **Instance**: one 0–100 row per entity per `anomaly.score` run, stored with its explanation (per Feature: observed vs baseline, deviation, reason) so it is recomputable.
- **Feature** — One **Measure** per entity per time bucket whose behaviour an Anomaly Model baselines.
- **Peer Group** — The cohort of entities (by a declared column, e.g. tariff plan) a Feature value is compared against when self history is short or as a second view.
- **Risk Score** — An explainable 0–100 number per entity (subscriber, account, device, SIM, dealer, channel, partner, or free-form): `Σ weight × indicator`, each contribution held to its factor's cap, stored with its **factors** so every score is recomputable.
- **Prediction** — The umbrella word for what the Predictive Analytics add-on produces: a **Customer Segment** assignment, a **Churn Score** or a **Forecast**, each stored with its inputs so it is recomputable.
- **Segmentation Model** — The component kind (a **Type**) that declares how entities are grouped (first slice: declared RFM bins and a label table).
- **Churn Model** — The component kind that declares a churn score: named **Inputs** (trailing-window entity Measures) with authored coefficients (the platform does not train in v1).
- **Forecast Model** — The component kind that declares a time-series forecast (seasonal-naive or Holt-Winters, with a stored backtest).
- **Consequence** — A **typed action a Decision Engine produces** (`route · tag · quarantine · drop · emit-signal · create-alert · start-job · trigger-pipeline · render-widget · generate-report · invoke-api`), executed via the Execution / Signal networks.
- **Decision Engine** — Anything that turns conditions/signals into **Consequences**: the rule kinds today, the AI **Assist** next (it *proposes* Consequences; a human approves — the approval is the consequence gate).

## Pipeline & Processing (ELT)

- **Pipeline** — A named, authored **DAG of Steps** that turns raw source files into clean, partitioned Tables.
- **Step** — One unit activity in a Pipeline: a processor with the uniform contract *Consignment in → Consignment out (+ rejects)*.
- **Step kind** — The registered **type** of a Step — the Type/Instance rule: *Step kind* is the template, *Step* is the node instance in a Pipeline.
- **Step Receipt** — The record one **Step** leaves for one **Consignment**, on one lane, in one attempt: rows in, rows per **outlet** (`data` · `reject:<reason>` · `route:<key>`, always the canonical spelling), where the data rests durably, a schema fingerprint, the outcome (`OK` · `FAILED` · `SKIPPED` · `PARKED` · `NOT_REACHED`) and bounded diagnostics — at most 1 KB.
- **Parser** — Reads a raw file of a given format (CSV, fixed-width, XML, JSON, EDI, ASN.1, …) into rows/columns — or, for tree-shaped formats, into records that must be flattened before they load into Tables.
- **Grammar** — The authored options that tell a **Parser** how to read one file format (delimiter + header for delimited, record element for XML, schema module for ASN.1, …).
- **Grammar Template** — A Grammar saved to the `grammar` component kind as a reusable **starting point**.
- **Pipeline Template** — A **Pipeline** config saved with `template: true` through the pipeline editor's *Save as template…*, listed by `GET /pipelines`, and offered as a starting point by onboarding's **Start from a template**.
- **Decode Profile** — One vendor's ASN.1 decode settings kept **once**, in a satellite `.toon` file whose single top-level block is `asn1:` (the same keys a Pipeline's `parsing.asn1` takes: `grammar_file`, `root_type`, `strictness`, framing lengths, `max_value_bytes`, `segments`).
- **Transform** — Reshapes/derives/aggregates (cubes) data.
- **Enrichment** — Augments each record via lookup against reference data.
- **Guarantee** — A declared property of a Pipeline that the runtime honors regardless of chain shape: `file_dedup` (path / fingerprint / marker), `backup`, `quarantine` (always on — keys only tune location/retention), `markers`, `gap_watch`, `retention`.
- **Pipeline Document** — A **generated**, human-readable specification of one Pipeline — source, Steps, the field-level Mapping + transformation tables, Guarantees, outputs, with worked sample rows from dry-run — used for business verification and sign-off.
- **Streaming Ingest Mode** — A **decode and execution strategy**, not a data origin: records are decoded and pushed **one at a time** rather than materialized as a batch, and a plugin ingester picks one of two execution modes **per batch, by size** (*generation* or *union*).
- **Sink** — Writes processed records to a destination.
- **Load** — The third **definition stage/drawer** in the unified pipeline editor (**Collector → Parse → Load**): create the **Schema** (derive from the parsed sample or import), author the **Mapping** (per-field rules incl. verbatim DuckDB scalar `EXPR` transforms), and set the **Table** write (Sink properties; format `PARQUET | CSV`).
- **Trigger** — The start condition of a run.

## Orchestration (what runs, and when)

- **Executable** — The abstraction for anything the Scheduler can start and that produces a **Run**.
- **Job** — An atomic, cron-style Executable that can do *anything* to data **at rest**: the downstream consumer of what a Pipeline landed.
- **Scheduler** — The Operations engine that owns **Triggers** and starts **Executables** (Pipelines or Jobs).
- **Run** — One execution of an Executable.
- **Archive** — A **container file** the operator drops in the inbox that holds many inner files: `.zip`, `.tar`, `.tar.gz`.
- **Entry** — **One inner file of an Archive.**
- **Unpack** — The **Collector-level stage** that expands compressed and archived inbox candidates into plain files before freezes the candidate list.
- **Expression** — A `$`-token an author writes in place of a literal value, **resolved at fire time** against the Run's context: `$today` · `$run.actor` · `$signal.<path>` · `$day(-1)` · `$upstream(<job>).artifact(<name>).<attr>`.
- **Platform Service** — An engine facility exposed to Jobs, packs and (stage 2) executable Steps through the typed lookup, granted by a declared `requires:` list that **fails closed at registration** (unknown or build-absent service id refuses the type/pack).
- **Execution pool** — A named, server-defined admission tier for **Consignments** (`scheduler.toon` `pools:`), chosen by a Pipeline with `processing.pool`.

## Data plane (Lakehouse)

- **Dataset** — The umbrella for any queryable relation the BI layer can bind to: **Table** \| **Derived Table** \| **Reference Dataset** \| **View**.
- **Table** — A Hive-style root directory of **Parquet** files, **partitioned by date / partition key** and **split by event type**.
- **Derived Table** — A materialized Table produced by a Transform or cube/rollup. (≈ materialized view / mart / OLAP cube.)
- **Reference Dataset** — A **Dataset produced from a Reference origin** (§3): cached / versioned **dimension** data (SCD), deduplicated from incremental or full-dump loads.
- **Lookup** — A Type defined **over a Reference Dataset** that resolves a key to the matched row or value, by **exact** or **best match** (longest prefix, range, as-of, fuzzy), with a multi-match policy and a not-found value.
- **Matrix** — The **intended user-facing name** for a summary / cube / roll-up data asset.
- **View** — A virtual (logical) query over a Table, Derived Table, or View.
- **Partition** — A physical partition of a Table (the unit of partition pruning).
- **Store / Storage** — The **physical** backend that holds the Parquet/partition files.
- **Consignment Selector** — The resolver that decides **which files a read actually names**.
- **Watermark** — **Event-time completeness for one output Dataset/table**: `min over producers of max(event_time_max)` over the Consignment catalog's non-superseded rows.
- **Window** — An **event-time interval `[lo, hi)` of one Stream Dataset** over which a **windowed Alert Rule** evaluates its Measure per key, on each commit.
- **Window buffer** — The **derived state of windowed Alert Rules**: a DuckDB table per (Dataset, rule set) holding only the columns the rules read and only rows whose windows may still be open; appended from each committed Consignment's own files, trimmed past `size + lateness`, rebuilt from the committed files at boot.
- **Pattern** — A **windowed Alert Rule shape an aggregate cannot express**, authored as `pattern:` beside the rule's `window:` block: `sequence` (an event matching step A, then one matching step B for the same key, `a ≤ b ≤ a + size` on event time; each step its own Condition Language tree; fires once per key and A event) or `absence` (a key — or the whole Stream — that had an event in the slide before a Window and none in it; judged only once the **close frontier** passes the Window's `hi + lateness`; one Alert per silence).
- **Close frontier** — **How far an absence Pattern has judged its Windows**: `max(Watermark, clock floor)`; a Window is judged once, when the frontier first reaches `hi + lateness`.
- **Clock floor** — **The wall clock standing in for the Watermark when a Stream is silent**: a silent feed sends no commit, so its Watermark never reaches the end of the Window an absence waits on; a tick raises the close frontier to the clock and judges absence Windows only.
- **Detection latency** — **The time from an event's arrival at the broker to the Alert that names it**.
- **Query** — A first-class, reusable **executable knowledge** Component: `{ type (sql \| structured), source Dataset, text \| model, Parameters }`.
- **Parameter** — A runtime binding in the **`$`-namespace** (`$today`, `$day(-7)`, `$current_user`, `$role`, or a user-declared `$name`) resolved from a **Parameter Context** just before a Query runs.
- **Result Set** — The **semantic description of a Query's output**: columns with type + analytic role (dimension / measure / temporal) + cardinality.

## BI / Visualization

- **Visualization Type** — A reusable **template** for a visualization: chart type, table type, graph, map, etc. It is a **Component Type** (declares a config schema).
- **Widget** — A **Visualization Type + Config + a binding to a Dataset's resultset metadata** — i.e. the configured, renderable **instance**.
- **Dashboard** — A layout (grid) of Widgets (tiles), shared per Space.
- **Viz Library** — The Studio pane listing every saved **Widget** (searchable by text / viz type / tags; each card can be viewed standalone, edited in the **Widget Builder**, or placed on a Dashboard).
- **Query Library** — The Studio pane (`/studio/queries`) listing every saved **Query**; authors SQL + `$`-**Parameters** and previews the **Result Set** offline.
- **KPI** — A single-number **Measure** with a target/threshold, rendered as a headline tile (mini → standard → max).
- **Measure** — A BI aggregation (SUM, AVG, COUNT, …) over a Dataset.
- **Column Role** — What one Dataset column is, stored as `columns[].role` on the Dataset registry entry: ONE vocabulary for the key that the Studio Dataset editor and materialization seeds already write (`dimension | measure | temporal`) and Link Analysis widens.
- **Report** — A **scheduled delivery of rendered output**: a Dashboard (or other rendering) exported on a **Trigger** to a channel / recipient list in a chosen format (CSV / PDF / PNG), authored on the *KPI & Reports* page and executed as a **Job**.
- **Insight Type** — A **template** for one kind of finding about a business **Measure**: `change`, `driver`, `anomaly`, `trend-break`, `forecast`, `target-risk`, `concentration`, `distribution-shift`, `segment-migration`.
- **Insight** — One computed finding of an **Insight Type** about a Measure, for one slice and one period: value, expected value, delta, impact, a 0–100 score with bands, its explanation parts and the structured query that reproduces it.
- **Insight Profile** — The authored Component (kind `insight-profile`) that says which Measure or **KPI** to watch, across which dimensions, with which Insight Types switched on and how they are tuned.
- **Chart Marker** — A visual overlay drawn on a **Widget**: a band (forecast, baseline, target), a point (anomaly), a reference line or an event span.
- **KPI History** — The stored value of a **KPI** per period, kept as a **Dataset** so a KPI can be charted, forecast and watched over time.
- **Reconciliation** — A comparison between two **Datasets** on matching keys (optionally with tolerances) that produces **Breaks**.
- **Break** — One unmatched or mismatched record found by a Reconciliation, typed **missing-left | missing-right | value-break**.
- **Settlement Agreement** — The effective-dated commercial terms with one partner for one service.
- **Settlement Statement** — A partner's document of what it says is owed for a period; versioned, with a control total.
- **Settlement Cycle** — One period of an agreement between statement dates; the unit of netting and of a dispute **Case**.
- **Settlement Position** — Per netting group and cycle: payable, receivable and net, in both currencies.
- **Dispute** — A **Case** grouping the **Incidents** sent to a partner for one Settlement Cycle.

## Observability

- **Signal** — A lightweight **emitted fact** — it *announces, never decides*.
- **Event** — A **view** of a Signal on the operational activity stream (file collected, Run started/finished, error).
- **Metric** — An **observability** time-series signal (throughput, error rate, lag) derived from Signals.
- **Alert** — A fired instance of an Alert Rule (severity: info / warning / critical) — the `ALERT_FIRED` **view** of the signal ledger.
- **Notification** — Delivery of a Signal to a channel (email, webhook); a **consumer** of the ledger.

## Incident & Audit

- **Incident** — A tracked operational problem.
- **Runbook** — Linked **guidance** for the person working an Incident or Case: a title, a summary, ordered steps (each optionally linking a Dataset, Query, Dashboard or Case), an owner role and tags.
- **Annotation** — The umbrella term for **user-authored metadata hung off some other entity**: today a **Note**/attachment (D10) or a **Tag** assignment (D7).
- **Annotation Target** — What an Annotation is attached to: `"object"` (an Incident/Case) plus every writable component type — Dataset, Dashboard, Widget, and the saved `link-analysis-view` / `geo-map-view`.
- **Admiralty grade** — The two-axis grade an analyst puts on an Investigation annotation: the standard NATO/Admiralty scale, **source reliability A–F** (F = cannot be judged) × **information credibility 1–6** (6 = cannot be judged), written as one token such as `B2`.
- **Tag** — A **user-created** label attached to any **Annotation Target** for cross-cutting grouping/filtering (the mail metaphor's "labels").
- **Tag Rule** — A saved search that applies a Tag (the Gmail-filter metaphor): it auto-tags newly created Incidents/Cases that match its criteria and can be **applied in bulk** to existing matches.
- **Case** — A group of related **Incidents** managed as one larger investigation with a shared resolution.
- **Merge** — Combine two or more Cases into one **surviving** Case managed as one: members, tags and watchers move to the survivor; the absorbed Cases close with a `MERGED_INTO` trace link and marker.
- **Split** — Carve chosen member Incidents out of a Case into a **new** Case managed individually, tied back by a `SPLIT_FROM` trace link; the original keeps its remaining members.
- **Findings** — A Case's resolution artifact (the loose, business counterpart of the Incident **Postmortem**): **Disposition** + **Impact** + records affected + summary.
- **Impact** — The typed money an **Incident** or **Case** stands for: **suspected · confirmed · recovered · prevented** amounts in one ISO 4217 currency, with a period and a basis.
- **Findings field** — One question the Findings panel asks (Disposition, Records affected, a desk's own "Root cause category", …).
- **Disposition** — The decided outcome an **Incident** or a **Case** resolves with (built-in ladder: confirmed · false-positive · recovered · written-off · inconclusive · duplicate · accepted-risk; wire values `CONFIRMED` … `ACCEPTED_RISK`).
- **Case Rule** — A saved search that **auto-groups Incidents into a Case** (C5): when ≥ *threshold* Incidents match its filter within a *window*, they are grouped under one Case (opened, or attached to the rule's still-open Case).
- **Escalation Rule** — What the SLA sweep does to an operational object that **breaches** an SLA target (response or resolution) or reaches an **age**: reassign it, notify (an `OBJECT_ESCALATED` event at WARN, picked up by the built-in `builtin-escalation` notification rule) and/or raise its priority one step (LOW → MINOR → MAJOR → CRITICAL, never past CRITICAL).
- **Triage / Triage Run** — A **Triage** is the Assistant's **RCA playbook**; a **Triage Run** is **one run of a Triage against a single Incident** (the Instance): trigger signal, timeline, hypotheses, outcome and any draft fixes.
- **Incident Brief** — What the Assistant's agent produces when it works **one Incident**: why it fired, cited evidence, a *declared* value at risk, and at most one proposed **Consequence** filed as a four-eyes **Action Request**.
- **Investigation** — The Link Analysis **enquiry object**: an ordered, replayable log of analyst ops (`seed`, `expand`, `exclude`, `hide`, `keep`) over a graph, plus the Working Set it evaluates to.
- **Graph Run** — One execution of one Link Analysis graph algorithm (of 29) on the server over an Investigation's Working Set, started with `POST /inv/graph/runs`, polled, cancellable, and ending in exactly one of `COMPLETED`, `CANCELLED`, `BUDGET_EXCEEDED` or `FAILED`.
- **Draft** — One analyst's **private, forkable copy of an Investigation's working state** (its op log, groupings and dynamic filter lists, evaluated Working Set and Graph Run results), forked from a pinned baseline of the Investigation and **promoted** back into it (rebase, conflicts reported; `D18`).
- **Working Set** — What an **Investigation** currently shows: the entities and links its op log evaluates to, recomputed by replaying the log (`/replay`) and sealed per step.
- **LA level** — Which Link Analysis screens an installation has: **Explorer** (the graph, Expand, browser algorithms, Entity Lists, saved views; every edition) or **Investigations** (adds the **Investigation** surface: op log, Drafts, Dossier, Graph Run, link index, Alert Rules on Investigations), which needs the billable **Investigations add-on** (`INS-AO-LA-INVESTIGATIONS`, included by default on Standard and above, removed with `-Daddons.laInvestigations=false`).
- **Snapshot** — The **frozen content of one analysis as it stood when the analyst saved it**, optionally attached to a **Case**.
- **Saved view** — A **named graph an analyst keeps**: the query or start it was drawn from, its display state and the Entity Lists it uses.
- **Canvas mode** — **What a drag on the canvas does**; exactly one is active: **Pan** (the default, `Esc` returns to it; Shift+drag still draws a lasso), **Lasso** (`L`, a drag selects), **Fisheye** (`F`, drag the magnifying lens over the graph) and **Link filter** (drag a lens; only the links inside it show).
- **Dossier** — The **evidential report of an Investigation**: summary, chronological ledger, every exclusion with its author and reason, negative space, and a SHA-256 chain of custody that `POST …/dossier/verify` re-checks against the store.
- **Masking mode** — Which entity ids an Investigation response returns **masked** as `masked:<16 hex>`: `typed` masks ids whose **Entity Type** is a masked type (including by Dataset column classification), `all` masks every id, `none` masks none.
- **Embed link** — A **read-only, revocable, expiring URL to ONE Investigation** for someone with no login: a live view of its **Working Set**, notes and references, masked exactly as the Space's **Masking mode** masks an Investigation read, never framed (link-only).
- **Value Measure** — A **Measure** that scores *entities* over the **whole Dataset** in a stated time window (at most 31 days, UTC) against visible thresholds: `passThrough`, `velocity`, `timeToCashOut`, `cashOutConcentration`, `structuring`, `benefitTransfer`, plus the non-alertable `valueWeightedLinks`.
- **Purpose** — The **stated reason or legal basis** an analyst gives when starting an **Investigation**: a required field, sealed into the Investigation header and shown in the **Dossier**, recorded but never enforced.
- **Preset query** — A question an industry already asks of its relationship data (*Reached by many*, *Top counterparts of one entity*, *Money in, then out again within hours*), run over one **Dataset** with a few parameters and answered as a table that *Draw these* turns into a graph.
- **Diagnosis** — An AI-assisted root-cause analysis of a failing Run or Collector that produces an **Incident** with a suggested fix.
- **Audit Log** — The append-only *who-did-what* trail.

## Component Metamodel (cross-cutting)

- **Component** — A configured, named, persisted **instance**: `{ kind, name, config, parts?, wiring? }`.
- **Component Type** — The reusable **template** that declares a Component's allowed parts, wiring strategy, and config schema. (A *Visualization Type* is a Component Type whose instances are Widgets.)
- **Part** — A child-Component reference inside a composite, with an optional per-use config override.
- **Wiring** — How a composite's parts connect: `graph` (Pipeline) \| `layout` (Dashboard) \| `schedule` (Job) \| `mapping` (Widget channels) \| `none`.
- **Registry** — The **derived** reuse graph over Components (composition ∪ reference).
- **Pending Change** — A human config change that a Space's **Approval Policy** held for approval instead of writing: the proposed content, the kind + name it targets, the base version the author saw, the author, a reason, created / expires-at.
- **Pending Action** — An operational action — a run's trigger, pause, resume, reprocess, rejects replay, retry, drain; a Job's trigger or a Job Run's replay — that an unattended **machine agent** asked for, held for a person to approve before it runs: the recorded request, the machine that asked, a reason, created / expires-at.
- **Action Request** — An outbound API call raised from an **Incident** or **Case** (by a person, or by a Decision Rule's `invoke-api` consequence) and held for a second person's approval before it is sent: the target **Connection**, the method, the payload rendered at creation, an idempotency key, and its delivery — attempts and the last response.
- **Regulatory Report** — A regulator-format document (a SAR / STR is the motivating case) assembled from ONE **Case** or **Incident** — its fields, its member Incidents and its evidence (attachment notes) — plus the values its maker types (the narrative), rendered ONCE from a **Report Template** and fixed from then on.
- **Report Template** — The definition of one regulator format: its output **fields** (each a source path into the report context, or a constant), the format (XML, CSV, JSON) and the **file drop** a submitted report lands in.
- **Submission (of a Regulatory Report)** — Writing an approved report's exact bytes to its template's **file drop** (the only delivery built: no live regulator API).
- **Egress Allowlist** — The per-Space list (`egress.toon`, `GET|PUT /settings/egress`, `canAdminister`) of host names and CIDR ranges an **Action Request** may reach although the egress policy denies their address class by default (loopback, link-local, private, CGNAT, this host…).
- **Approval Policy** — The per-Space, per-kind setting (`approval.toon`, `GET|PUT /settings/approval`) that says which config kinds need a Pending Change, which capability may approve one, and whether four-eyes applies.

## Graphs & Relationships

- **Graph** — A queryable relationship object: **Nodes** + typed **Edges** that can be traversed, analyzed (paths, centrality, communities), and rendered.
- **Node / Edge** — The *generic rendering* primitives shared by one renderer.
- **GraphSource** — Where a Graph's nodes/edges come from.
- **Lineage vs Provenance** — **Lineage** = the *derived asset graph* (which asset feeds which); design-time, structural.
- **Entity / Link** — An **Entity** is a business node (a caller, an account); a **Link** is a business edge between Entities (a call, a transaction) carrying typed attributes (call-type, duration).
- **Entity Projection** — The **mapping** (not a store) that folds a **Dataset**'s rows into an Entity/Link graph: column → source Entity, column → target Entity, optional columns → Link type/attributes.
- **Inspecto LA** — The **product** that sells Link Analysis: the standalone `la-app` (title, header, sign-in screen, browser tab) and the documents written for its buyers and users.
- **Link Analysis Studio** — The Builder-lens Studio pane (`/studio/link-analysis`) for graph investigation: pick a **GraphSource** + query, render via the shared G6 host, analyze (paths, neighborhood, centrality, communities).
- **Link Analysis limit** — One configurable bound of Link Analysis (a cap, budget, timeout, page size, pool size or rate), declared once in the catalogue with a default and an allowed range and enforced by the server.
- **Entity Type** — A named kind of business identifier (`subscriber`, `imsi`, `imei`, `msisdn`, `wallet`, `account`, `agent`, `handset`, `cell`), configured **per Space** in `link-analysis.toon`.
- **Entity Type family** — The neutral group every **Entity Type** sits under, from a closed core set: *Party · Organisation · Account · Identifier · Device · Place · Document*.
- **Value shape** — What one value of an **Entity Type** looks like, from a closed vocabulary: `free · e164 · digits(n) · luhn(n) · iban · email · uuid` (a range `a-b` for digits and luhn).
- **Record type** — What one row of a **Dataset** is in a domain (a voice call record, a wallet transfer, a registration), defined by the Space's **Industry packs** with the Entity Types such a record usually holds.
- **Domain Profile** — The **Industry pack** a Space reads Link Analysis in: which words name the canonical concepts (the working-set tiles, the two ends of a link, Entity Types, link kinds, Value Measures, patterns), with an abbreviation and a hover definition for each.
- **Entity Type Profile** — What the Space's Datasets say about one **Entity Type**, computed on demand and cached until a new File lands: the Dataset columns bound to it, volume and fill rate, sentinel values, value shapes, time span and per-day timeline, freshness, lineage, link and relationship statistics.
- **Entity Profile** — The same facts for one **Entity** (a typed key): first and last seen, active days, where it appears, degree and its percentile among its type, related identifiers.
- **Entity List** — A named, persisted, Space-scoped set of typed Entity keys with a stated purpose (`allow` · `block` · `watch` · `exclusion`), held as a fold over the Space's **Identity Fact** log, so it can be read as of any log position.
- **Category list** — An **Entity List** of purpose `exclusion` that an administrator keeps (`ownerKind: admin`, capability `canManageExclusionCategories`): marketing VIPs, politicians, defence, intelligence.
- **Identity Fact** — One immutable record in a Space's append-only identity log (`audit/entity-facts/<seq>.json`), SHA-256-chained to its predecessor, always carrying an actor and a reason; the chain is re-verified on every read.
- **Resolution Group** — A set of records judged to be one entity **deterministically**: they share a block (equal **blocking keys**) and agree exactly, after normalising, on every column of one **match condition**, closed transitively; its id is the smallest member key.
- **Screening** — Comparing subjects (a name and/or an identifier) against **Entity Lists** of any purpose (sanctions, PEP, deny lists) and reporting a **Match Score** per candidate entry.
- **Match Score** — How alike a subject is to one Entity List entry, 0..1 (4 decimals): 1.0 for an identifier match (exact under the list's sealed normaliser, or inside a prefix / range / CIDR entry); for a name, the fold-and-token-set score of.
- **Screening Run** — One run of a Job whose Job Type is `screening.run`: every row of a Dataset screened against named Entity Lists, each new match raised as a **Screening Hit**.
- **Screening Hit** — One match at or above the threshold, raised by a Screening Run and awaiting or carrying a reviewer's decision: `open` → `confirmed` · `dismissed` · `escalated`; `escalated` → `confirmed` · `dismissed`.
- **Geo Map Analysis Studio** — The Builder-lens Studio pane (`/studio/geo-map`, Phase 1) for geographic investigation: pick a **GeoSource** + **GeoQuery**, render on the offline MapLibre host, investigate (search, nearby, heatmap, time filter).
- **GeoSource** — Where a map's points/routes come from — the geo seam parallel to **GraphSource** (one map renderer + one query seam + many sources).
- **GeoQuery** — A GeoSource's saved query configuration: Dataset + location/entity/kind/time column mapping + filters.
- **GeoPoint / GeoRoute** — The generic map-rendering primitives, the geo analog of Node/Edge.
- **Geo View** — A saved geo investigation (Component kind `geo-map-view`): GeoSource id + GeoQuery + display options + camera.
- **Layer** — A toggleable stratum of the map display: the offline **basemap** layers, the data plane (points/routes), and overlays (heatmap; Phase 3 boundaries/custom GeoJSON).
- **Geocoder** — The pluggable seam that turns a place *name* into candidate coordinates (the "find place" jump), parallel to **GeoSource**.

## Assistant

- **Assistant** — The AI helper that answers questions, drafts Pipeline/Config, validates Expectations and Alert Rules, and explains errors.
- **Tool Evidence** — **A provenance-tagged value produced by one Assistant Tool**: the value plus a credibility tier, a source reference, a confidence and an observation time.
- **Model Settings** — AI model selection, keys, and generation parameters used by the Assistant and Diagnosis.
- **Agent Kit** — What lets an AI agent running outside Inspecto (Claude, Gemini, OpenAI or a local model) build, ship and manage Apps on a running install: the MCP endpoint with its MCP Tools, the Agent Skills, and one package per agent vendor.
- **Agent Skill** — One job an outside AI agent can do on Inspecto, written in the open format: when to use it, its steps as MCP Tool calls, its guardrails and links into the Handbook.
- **MCP Tool** — One task-level operation the Inspecto MCP endpoint offers an outside agent (for example `describe_dataset`, `dry_run_pipeline`, `propose_action`), run as the signed-in person or a machine identity; every write goes validate → dry-run → Draft, and every outbound or promoting act becomes an Action Request for a human to approve.

## Capability areas (the functional spine)

- **Control API** — The versioned HTTP control plane: the `/api/v1` business contract, its envelope and error-code catalog, the OpenAPI document, ETag concurrency, `GET /bootstrap`, and the Java embedding API's stability policy.
- **Edition** — A **build flavour** of one Inspecto version — **Basic** · **Standard** · **Advanced**, plus **Preview** (everything, demo sign-in, never sold) — assembled by `package.ps1` from Maven profiles and modules.
- **Compliance** — The controls, evidence and packaging obligations that let a deployment pass an external audit (SOC 2 / ISO 27001 / HIPAA / PCI scope): SBOM per bundle, signed releases, the dependency-review baseline, and the controls matrix.
- **Compliance Control** — **One row of the controls matrix**: an obligation stated by an external framework, mapped to what this product does about it, who is responsible and which evidence file attests to it. 🔴 **Its identifiers are externally owned and there is no product-side control id** — the matrix is keyed on SOC 2 TSC, ISO 27001:2022 Annex A and NIST 800-53 identifiers, and `controlId` appears nowhere in the code.
- **Compliance Evidence** — A hand-written, git-tracked attestation under `compliance/evidence/` that a **Compliance Control** holds, each naming the matrix gap it closes; the SBOM is the one machine-generated member.
- **Guard** — A repo-level check that fails the build or the push when a stated invariant is broken: the vocabulary, secret, doc-link, gate-tally, dependency-review and coverage guards plus the processor-board `--check`.

## Module architecture

- **Platform module** — A horizontal Maven module that the rest of the system builds on (for example `inspecto-engine`): its **Build role** is *Platform module*.
- **The three axes of a module** — every module is classified once on each axis; the axes answer different questions.
- **Offering** — A sellable composition of modules and content, declared in `offerings/<id>.toon`: modules, UI features, packs (Space Templates, Pipelines, Dashboards, Alert / Decision Rule sets) and default Space settings.
- **Product Map** — The commercial tree of everything Inspecto offers, laid out like a mind map (Layer → Module → **Functionality**, plus Add-ons, Solution packs and Editions), used for pricing, support and customer-specific builds.
- **Product Map Item** — One node of the Product Map, carrying a `billable` flag and, when billable, an **Order Code** and an `enforcement` (`build` · `enabled-gate` · `contract` · `runtime`) saying how a sale is honoured.
- **Functionality** — A Product Map Item that a customer recognises inside a module (for example "Maker-checker approvals"); it can be priced but usually cannot be left out of a build.
- **Order Code** — The stable code that identifies a billable Product Map Item on a quote, invoice or bill of materials.
- **Add-on** — A horizontal, domain-neutral Optional module set sold to any customer (Incidents, Case Management, Reconciliation, Scoring & Lists, Action Requests, Regulatory Reporting, Workflow & SLA, Link Analysis & Investigations, AI Assist & Intelligence, Integration & Delivery, Premium Connectors, Multi-entity / Group).
- **Solution pack** — Mostly-content bundle of Space Templates that **requires** Add-ons.
- **Product assembly** — five layers, **Base** modules → **Add-ons** → **Industry** → **App** → **Product**, across three axes: **Edition**, **Distribution** and **Entitlement**.
- **Industry** — A vertical that Apps are built for (*Telecom*, *Mobile money*), declared by its **Industry pack** and named by that pack's id (`telecom`).
- **App** — A finished job, either for one **Industry** (Revenue Assurance, Fraud Management and Complex event processing for *Telecom*) or **Industry-neutral** (Link Analysis, Case Management: any Industry, with the Space's Domain Profile giving the words).
- **Product** — What a customer receives, declared in `products/<id>.toon` with its brand, its shell and the Editions it comes in.
- **Suite** — One install running several Products over the same Spaces, with an App switcher across them.
- **Distribution** — How one Product build ships: a kind (`demo`: golden data, Demo Users, a guided tour · `trial`: time-boxed by its Entitlement · `pilot`: the customer's Collectors pre-wired, no data · `production`) and a target (`windows` · `linux` · `container`, an OCI image plus a Helm chart · `airgap`).
- **Entitlement** — The signed file listing what one customer's build may switch on: Apps, Add-ons, Edition, node count and expiry.
- **Assembly Plan** — The JSON the assembler writes for one Product × Edition × Distribution × target: the module closure, the classpath order, the UI host and App libraries to build, the content to stage, the Spaces to seed, the docs and the SBOM scope. `package.ps1` executes it.
- **Composed Space Template** — The Space Template a Domain product's build writes from its Apps' templates, so Apps that share one Space need no new Java: the parts' files side by side, plus its own `template.toon` and SLA examples; a file two parts both ship is refused.
- **Product lock** — `products/<id>.lock`, committed for every released Product: the exact versions and content hashes of every module, App, Industry and Space Template in it.
- **Module manifest** — A module's declaration of what it **provides** (contracts, capabilities, routes, config kinds, store families) and **requires** (contracts, other modules).
- **Installed · Enabled · Permitted** — The three gates, in order.
- **Removal semantics (inert config)** — Config that references an absent module **loads inert**: shown with a diagnostic naming the missing module, never rewritten, normalised away or dropped by a save.
- **Decision Kernel** — The base capability every **Decision Engine** (§4) runs on: the **Condition Language**, the when / if / then model and the **Consequence registry**.
- **Condition Language** — The **condition tree** in which every Decision Engine states its condition.
- **Consequence registry** — The open contribution point where modules register **Consequences** (§4).
- **Model Escalation Ladder** — a procedural, synchronous LLM retry ladder triggered by a confidence threshold.
