## 3. How editions gate a feature today (survey)

There are three independent mechanisms. A change picks one or more.

1. **Module presence (Offerings and Maven profiles).** `offerings/<edition>.toon` lists the jars an edition stages;
   `pom.xml` has `edition-standard`, `edition-preview`, `edition-advanced` profiles (Basic is the default build,
   about lines 87-210). A missing module gives stub routes that answer 503 naming the module (`AbsentModuleRoutes`).
   The matrix in `EDITIONS.md` is generated by `tools/render-offerings-matrix.mjs` (`--check` runs in CI).
   *Limit:* `la-storage`, `la-core`, `la-api` and `geo-link` are one staged set, so nothing inside them can be dropped by
   removing a jar; that needs a new module first.
2. **Edition features (runtime, jar present).** `platform/inspecto-etl/.../EditionFeatures.java` holds the constants
   (lines 37-57: `ALERT_DISPATCH`, `SINK_ARCHIVE`, `SINK_DUCKLAKE`, `PII_MASK`, `INVESTIGATIONS`), `present(feature)`
   (line 71) ServiceLoads every `EditionFeatureProvider` (line 188; a provider that fails to load counts as absent, so it
   fails closed), and `overrideForTest(Set)` (line 180) is the test seam. Providers: `OpsEditionFeatures.java:21`
   (`ALERT_DISPATCH`, `INVESTIGATIONS`), `BackupEditionFeatures`, `PolicyEditionFeatures`. Two kinds:
   - **Config features** refuse with `422 ERR_EDITION_FEATURE` (`FindingCodes.java:79`, "run the Standard or Advanced
     edition"), at the save gate (`SaveGate.java:155-160`), at Pipeline load (`ConfigRegistry.java:166`), at boot load
     (`ServiceBootstrap.java:177`, `SpaceManager.java:454-475`, `TemplateSeedGate.java:115`), and at run time
     (`CollectorProcessor.java:416` refuses a remote acquisition before opening it; `RowShaper.java:314` refuses a mask
     step). `ProcessorCatalog` (`ProcessorCatalog.java:44`) has **no edition column**: "Standard+" appears only in
     free-text notes.
   - **Route features.** Only `INVESTIGATIONS` today. A `RouteModule.featureIds()` that names it is answered
     `503 CAPABILITY_UNAVAILABLE` when absent (`ControlApi.requireModuleEnabled`, `ControlApi.java:1714-1721`), before
     the Space-level `MODULE_DISABLED` 404. `EditionFeatures.gatesRoutes(id)` (line 103) is a **hard-coded single-id
     check**: a second route feature needs it generalised to a set, plus a matching `refusal()` text.
     `ModuleManifestGuardTest` pins that each module's `module.toon` `provides.features` equals its RouteModules'
     `featureIds()`.
3. **Per-Space module switch (`geoLink`).** All 19 Link Analysis RouteModules return `Set.of("geoLink")` (for example
   `InvRoutes:88`, `GeoRoutes:64`, `PatternRoutes:65`, `EntityProfileRoutes:42`); `InvestigationRoutes:122` returns
   `Set.of("geoLink","investigations")`. A Space's `modules.toon` can disable `geoLink`, which answers 404
   `MODULE_DISABLED` for **every** `/inv/*` and `/geo/*` route (`ControlApiGeoLinkModuleGateTest`). It is a Space
   switch, **not** an edition gate, and it is all-or-nothing.

**How the SPA learns what is available:** `GET /bootstrap` (`BootstrapRoutes.java`): `edition()` at line 99 (`basic` when
`auth.mode` is none, `advanced` when an `AccessDecider` is installed, else `standard`), `features()` at line 104 minus
Space-disabled and edition-withheld route features (line 117), with flags such as `geoLink` and `investigations`. The SPA
reads them via `session.geoLinkEnabled` (`la-host.providers.ts:117`) and hides navigation with `navFeature: 'geoLink'`
(`navigation-data.ts:285,293,308`).

**Tests that pin edition behaviour today:** `ControlApiBasicEditionLinkAnalysisTest` (pins Basic as the explorer: one
route per explorer module works, one per Investigation module answers 503), `EditionFeatureGateTest`,
`EditionFeaturesTest`, `BootstrapEditionTest`, `ModuleManifestGuardTest`, `CapabilityManifestTest`,
`RowShaperMaskTest`, `CollectorProcessorArchiveEditionTest`. ⚠ `EditionFeatures.overrideForTest` is static and
per-JVM: a test that pins it must reset it to `null` in teardown.

### 4.1 Masking on Basic

- Masking is enforced at **render time** by `EntityMasking` (`la/inspecto-la-api`), on the way out of Investigation
  responses and the Dossier, driven by the Space's `maskingMode` in `link-analysis.toon`. It never masks at storage.
- Basic has no sign-in, so its masking is already **display only: anyone may reveal**. That rule is not edition code; the
  survey believes it follows from the absence of sign-in and of an audited-reveal gate (not confirmed).
- `transform.mask` (PII step masking) is a separate Advanced-only feature (`PII_MASK`, `RowShaper.java:314`); this plan
  does not touch it.
- **Options:** (a) *fix the mode to `none` on Basic and hide the setting* (recommended: it removes a control that
  protects nothing on a no-sign-in edition, and keeps the code and the enforced behaviour on Standard and up);
  (b) *remove masking code paths from Basic* (rejected: classified ids would show raw in Entity Lists and Industry packs,
  a security regression, and the code is shared); (c) *keep it as is*.
- Consequence to state in the doc whichever is chosen: on Basic, classified Dataset columns show **unmasked**.

types, in the base `entity-store` module (decision ED-5), and they stay in every edition under every option below.

## 6. Restricting continuous ingestion on Basic (request 5)

### 6.1 What Basic does today

- Collectors and acquisition (`platform/inspecto-acquire`, run by `CollectorProcessor`) and the Pipeline engine
  (`platform/inspecto-engine`, `platform/inspecto-etl`, the step catalog `ProcessorCatalog`, `EnrichmentService`) are
  **base**: present in every edition. Collector connectors (local file, SFTP, S3, and the `db` Collector with a watermark
  column, `DbExportConnector`) are in the `inspecto-connectors.jar` sidecar, which Basic stages. Kafka and the ASN.1
  decoder are already Standard and up by module.
- **One-off versus continuous already exists in code.** One-off runs: `POST /runs/{name}/trigger` (`RunRoutes.java:55`),
  `POST /trigger` (run all once, `RunRoutes.java:147`), `POST /runs/{name}/reprocess` (`RunRoutes.java:98`),
  `POST /pipelines/authored/{id}/trigger` (`PipelineGraphRoutes.java:77`). Continuous: the scheduler loop
  (`PipelineScheduler.java`, poll interval at lines 106 and 233, `dispatchCycle` at 266, `dispatchAcquireCycle`),
  decided per Pipeline in `dueThisTick` (about lines 482-492) from `PipelineTrigger.Kind`
  (`PipelineTrigger.java:41`: `SCHEDULE_INTERVAL`, `SCHEDULE_CRON`, `EVENT`, `MANUAL`, `DEFAULT_POLL`, `STREAM`).
  `EVENT` and `MANUAL` never run on the loop. Scheduled Jobs run through `JobRoutes` and the Job scheduler.
- **No edition gate on ingestion exists today** beyond `sink.archive`, `sink.ducklake`, `quality.pii.mask` and
  `alert.dispatch`. Nothing gates CSV, Postgres or Parquet Collectors, `transform.*` steps or enrichment by edition.

### 6.2 The smallest design (a proposal, not existing code)

1. **Declare features** in `EditionFeatures`, for example `ingest.continuous` and `ingest.transform`, with a `refusal()`
   text case, declared by a Standard-only `EditionFeatureProvider`. Basic reads them as absent. No jar change.
2. **Save and load gate.** Extend `EditionFeatures.pipelineRefusals` (the draft overload at line 113 and the parsed one at
   line 149): refuse a non-manual trigger (and any step tagged Standard and up) when the feature is absent, as
   `422 ERR_EDITION_FEATURE`. That reaches `SaveGate.java:155`, `ConfigRegistry.java:166` and `SpaceManager.java:454`.
   The existing mask walk (`maskRefusals`) already handles nested route branches and is the model.
3. **Run-time gate.** In `PipelineScheduler.dueThisTick`, return false for a non-`MANUAL`, non-`EVENT` trigger when the
   feature is absent; guard the acquire driver (`dispatchAcquireCycle`, `CollectorService.java:764,1276`) so a polling
   Collector never starts. This also covers a config copied onto disk that skipped the save gate (precedent:
   `CollectorProcessor.java:416`). **Manual `trigger` and `reprocess` stay open**, so Basic keeps one-off loads.
4. **Step catalog.** Add a machine-readable edition (or feature) field to `ProcessorCatalog.Processor` (today
   `(family, id, emoji, icon, label, status, nodeType, capability, note)`), so the UI can mark steps Standard and up
   and the save gate can refuse them from one list.
5. **UI.** Expose the flags through `/bootstrap`; hide or badge continuous triggers and gated steps on Basic.

**Why gate by trigger mode, not by Collector type.** The request names three formats (CSV, Postgres, Parquet). A gate on
trigger mode covers them all with one rule; per-format gates would multiply the surface and diverge. The format choice
that remains open is whether Basic keeps the Postgres (`db`) Collector for **one-off** manual pulls (D-LAE9).

**What breaks (breaking changes are free here, no shims: operator standing preference).** An existing Basic install with
a scheduled or polling Pipeline, or any Basic config using a gated step, is refused at load after the change. State this
in the release note; build no migration path.
