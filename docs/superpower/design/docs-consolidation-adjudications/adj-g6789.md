## Group 6 — `StreamingFileIngester` / parsing frontends

### 6.1 — the plugin config home is a 3-tier precedence (+ a 4th exclusive spelling)

`parsePlugin` (`inspecto-etl/src/main/java/com/gamma/etl/PipelineConfigParser.java:1069-1133`) picks
**one** `pluginBlock` whole, then falls back **per key** to the legacy `processing.*` triple:

```java
// :1078-1080 (the code's own comment states the precedence)
// Inline first, then the referenced Grammar's own plugin root (an extracted `parsing:` block
// carries it too), then the legacy processing.* triple.
Map<String, Object> pluginBlock =
        (parsing != null && parsing.get("plugin") instanceof Map<?, ?> pm)          // :1081-1083  TIER 1
                ? (Map<String, Object>) pm
                : (blockShaped && grammarBlock.get("plugin") instanceof Map<?, ?> gm) // :1084-1085 TIER 2
                        ? (Map<String, Object>) gm : null;
```

Then, per key (TIER 3 = the fallback arm of each ternary):

* `ingester` — `:1096-1097` `pluginBlock.get("ingester")` else `proc.get("ingester")`
* `ingester_config` — `:1098-1100` `pluginBlock.get("ingester_config")` else `proc.get("ingester_config")`
* `segments` — `:1103-1105` `pluginBlock.get("segments")` else `proc.get("segments")`

**The precedence, exactly:**

1. **inline `parsing.plugin.{ingester,ingester_config,segments}`**
2. **the referenced Grammar component's own top-level `plugin:` map** — reachable only when the grammar
   file is *block-shaped*, i.e. `isParsingBlock` = it carries a `delimited:` **or** a `plugin:` map
   (`:1923-1926`); a Grammar component is "just an EXTRACTED `parsing:` block" (`:948-950`)
3. **the legacy `processing.ingester` / `processing.ingester_config` / `processing.segments` triple**

The fallback is **per key**, but the block itself is chosen whole — tiers 1 and 2 are not merged.

**4th, mutually exclusive:** `frontend: asn1` synthesizes the block from the `asn1:` map
(`:1090-1095` → `asn1PluginBlock`, `:1683-1691`) and **refuses** a co-present `parsing.plugin` /
`processing.ingester`:

```java
// :1091-1094
if (pluginBlock != null || proc.get("ingester") != null)
    throw new IllegalArgumentException("frontend 'asn1' synthesizes its own plugin ingester — "
            + "remove parsing.plugin / processing.ingester, or use frontend 'plugin'");
```

Two other live refusals in the same method (must survive any merge):
* `:1106-1109` a plugin ingester with an absent/empty `segments` map is refused **at config load**
* `:1129-1131` `frontend: plugin` with no `ingester` anywhere is refused

**Verdict.** `plugins.md` documents tier 3 only; `parser-plugins.md` tier 1 only;
`parsing-options-reference.md:215-216` is the **only** file naming both — but it calls them "aliases"
and names **no** tier 2, so even the authority is incomplete. Bucket **UNDISPUTED-DOC** for all three;
the plan's ⛔ "a merge must carry that sentence" holds, but the sentence needs the grammar-block tier
added or it is still only 2 of 3.
