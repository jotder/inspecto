What breaks the uniform look, and where the SQL ↔ fields story stops

Grounded in the source, not the screenshot. Each row names the file to change.

Defect Inconsistent Decision
Defect
Native select popups render white on a dark app

No color-scheme is declared anywhere. The body gets a dark class, but the browser paints the option list, scrollbars and date pickers with its light palette. Declare color-scheme: dark beside the class toggle in the layout component. One line, fixes every native control in the grid.

Decision
SQL and fields are one-directional today, and the way back is destructive

Fields compile to SQL live. A hand-written Step opens in a SQL-only mode whose only bridge is "Start a field list from the incoming columns", which throws the SQL away. The recorded decision D4 says never parse SQL back into rows. Interchangeable editing needs a bounded reconciler, not a parser: projections only, catalog templates matched in reverse, everything else kept as a Custom SQL row. Main and SQL view artboards show the shape.

Inconsistent
Two control heights in one toolbar row

The search input is 32px, the filter pills beside it are 28px, the grid inputs are 32px and their parameter inputs 28px. Pick 32px for anything on the toolbar line and in a primary cell, 28px only for nested parameter controls and icon buttons.

Inconsistent
Borders come from two vocabularies

The drawer header uses the border token. The transform grid, its inputs, the SQL-only card and the empty state use literal gray-300 / gray-600 / gray-700 classes. The token guard only catches hex and rgb, so this passes CI. Extend the guard to palette border and text classes and route them through --gamma-border.

Inconsistent
Radii drift: 4 · 6 · 8 · 16px with no token

Badges 4px, inputs 6px, cards 8px is a fine ramp. The empty state's 16px dashed box is the outlier. Name the ramp once (--radius-sm/md/lg) and drop the outlier to 8px.

Inconsistent
Two eyebrow styles on the same pane

The drawer eyebrow is uppercase, tracking-wide, 60% opacity. The section label "Fields that come out" is uppercase, semibold, 70%. Make it one style. The eyebrow itself should read "Transform · map", the node kind and id, not the bare word TRANSFORMER.

Inconsistent
Overlays are patched two different ways

Menus, selects and autocompletes get a scheme-agnostic surface override. Dialogs get a dark-only token remap and lean on Material defaults in light mode. The confirm width lives in the service, not in the shared recipe. Both work today, but the popup sheet defines one surface recipe so the next overlay does not pick a third way.

Inconsistent
The generated SQL is a hidden toggle

"Show the SQL this produces" is a disclosure at the bottom. If SQL and fields are peers, the SQL is always visible read-only under the grid, and the view switch in the header is where editing moves.

What already holds up. One Step type for both views, one compiler, an execution-free DESCRIBE for types, only a real binder 422 blocking Apply, dirty tracking by comparison, unique-name refusal, row order as output order. The redesign keeps all of it.
