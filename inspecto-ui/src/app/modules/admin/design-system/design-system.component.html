Schema-driven form

<inspecto-schema-form> renders a Component Type's AttributeSpec[] with the platform's three-tier disclosure: required fields up front, optional collapsed, advanced behind the gear. dependsOn attributes show (and validate) only while their controller matches — switch the protocol to see the Host field appear and disappear. Prefer this over a hand-built form whenever the fields are plain config attributes. As of date carries a [tokens] picker: choosing one replaces the field's whole value, and [tokenSyntax] exempts it from the field's date pattern. 

{{ snippets.schemaForm }}

Schema columns table & column metadata

<inspecto-schema-fields-editor> is the shared raw.fields[] grid — include / # sequence / icon-only type menu / Name / Synonym — with search, filter, sort and paging that keep a 500-column feed usable. In Auto types mode the icon menu locks (inferred types are the sniffer's; switch to Declared to override). <inspecto-schema-metadata-grid> is a second view over the same rows signal, annotating description / unit / classification (Catalog-facing, never read by the ETL) — the host merges its values onto the columns table's rows by selector at submit. Both are pure: seed [rows] from a signal, read value() on submit.

The tabbed Grammar surface (AttributeSpec.tab)

A spec set naming ≥ 2 distinct tabs makes <inspecto-grammar-editor> render a tab group — one schema-form per tab, count badges for values set away from default, a warn dot on an invalid tab. The editor itself needs a served parser catalog, so (like <inspecto-collector-config>) it is documented here as a snippet rather than mounted — the live surface is any delimited Parse step in the Pipelines editor. ⚠ The R9 rule: tab panels live outside the mat-tab bodies, [hidden]-toggled, because MatTab instantiates body content on first activation and unvisited tabs would silently drop their values on save.

Resizable dialog

[inspectoDialogResize] (inspecto/components/dialog-resize.directive.ts) — the shared resizable / maximizable dialog chrome, extracted from the grammar dialog so every dialog resizes the same way. Put the attribute on the dialog title: it appends a drag grip to the bottom-right corner (pointer drag, or arrow keys when focused), and big dialogs add a maximize button calling chrome.toggleMaximize() — which reuses the existing .dialog-fullscreen panel class. Once sized, the content flexes into the chosen size instead of scrolling. Adopters: the Grammar editor and the Pipelines node-config dialog. Never re-roll a per-dialog fullscreen toggle. 

{{ snippets.dialogResize }}

Definition drawer

<inspecto-definition-drawer> (inspecto/components/definition-drawer.component.ts) — the shared shell for defining one pipeline object in an editor's right dock: title + kind header, an unapplied badge, projected definition content, and an Apply/Discard footer. Apply is always an in-memory patch — persistence belongs to the host's toolbar Save (one save path, definition-surface D2). A dirty close confirms first; the shell owns that guard. Non-modal by design: it is a dock resized by the host's [inspectoSplit] handle, never an overlay. Adopter: the Pipelines editor's Collector definition.

Inline AI assist

<inspecto-ai-assist> is the ONE inline authoring surface — panes adopt it, never fork it. The pane names a non-mutating agent tool and passes its own context as the tool's args, so the operator never re-states what the screen already knows. The surface renders the returned draft with its anchored findings and a diff against the current config; (applyDraft) fires only on an explicit click and the pane does the write through its own validated route — the human is the actor. It persists nothing, the backend refuses mutating tools with 403, and an absent intelligence module degrades to a disabled affordance rather than breaking the pane. Gated on canAuthorWorkbench. 

{{ snippets.aiAssist }}

Explain this screen

<inspecto-ai-explain> is the read-only sibling of the authoring surface: one icon button for a pane header that answers "what am I looking at" from docs/GLOSSARY.md, the binding vocabulary. The pane declares the terms — a free-text box would make it a docs search engine and would re-state what the screen already knows. It has no write path at all (no draft, no diff, no Apply) and is deliberately not gated on canAuthorWorkbench: a Business-lens user is exactly who needs the vocabulary explained. Everything it renders lives in a dialog, so it cannot disturb the header row it sits in. Backed by the non-mutating glossary_lookup, falling back to docs_search for an undefined term; an absent intelligence module renders an explanation instead of failing.

Data table

One <inspecto-data-table [tier]> (inspecto/data-table) consolidates every grid. Tiers, like phone versions: mini = the grid; standard = + search · filter · sort · CSV export; pro = + the offline SQL/query editor (projection, nested AND/OR, Advanced SQL); pro max = + save the query as a reusable rule template. The heavy logic lives in framework-free core/ (csv · quick-filter · controller) + inspecto/query; the component is a thin shell.

Tree table (aligned hierarchy)

<inspecto-tree-table> — an expandable indented hierarchy on the left with aligned value columns on the right (Community ag-Grid; no Enterprise tree-data). One component for breakdown-by-dimensions, multi-entry comparison, N-way reconciliation and file browsing. Cell plugins are ordinary columns ColDefs (here the Δ column uses varianceCell()); [rowActions] adds action icons and [multiSelect] adds checkbox selection. See tree-table-design.md.

Graph hosts (AntV G6)

Two patterns for node-graph views — both reuse canvasTheme() + nodeColor/nodeShape (never hardcode canvas colours). See the angular-ui skill §4. Live examples are on the Pipelines pane (Per-pipeline / Combined / Editor toggle) and the Link Analysis studio.

Read-only

catalog/graph-view.component — rebuilds the graph on every data / scheme change. For static visualisations (catalog graph, Pipelines Per-pipeline / Combined). Opt-in inputs (all default off; hosts stay byte-identical without them): [fill] grow-to-container, [display] per-kind colour/shape/pattern/size overrides, [tooltips] hover details, [emphasis] highlight/dim + community grouping, and [layout] — 11 selectable G6 layouts (GRAPH_LAYOUTS/layoutConfig(); the 3 tree layouts gate on the pure isForest()). Live with all options: the Link Analysis studio, which pairs it with the pure algorithm library inspecto/graph/graph-analysis.ts (paths, centrality, LP + Louvain communities, motif pattern matching).

Interactive editing (T32)

pipelines/pipeline-editor-graph.component — a persistent graph mutated in place (drop-to-add, two-click connect, delete), rebuilt only on subject change (graphKey). Live in the Pipelines Editor mode.

Map host (MapLibre GL)

inspecto/geo/map-view.component — the Geo Map Analysis analog of the read-only graph host: fully offline basemap (slimmed Natural Earth GeoJSON + bundled glyphs under assets/basemap/, no tile server), scheme-aware via theme/map-tokens.ts (the map's chart-tokens), pan/zoom, scale bar, fit-to-data, PNG export. Data plane: GeoData points render as circles; (pointClick) emits the point id. A pmtiles:// protocol is pre-registered for customer vector-tile archives (Phase 4).
