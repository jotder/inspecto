# Golden corpus (Phase 0 — REDESIGN.md §6)

Captured output of **today's legacy decoder** (`asn2.ASN1Reader` + `transformer2.Transformer`)
over every `config/` + `data/` pairing that works. This is the only objective definition of
"current behaviour" — **including its bugs**. The rewrite (asn-core/asn-schema/asn-transform)
is validated against these files; every intentional difference must appear in a written
deviation report, never silently.

## Regenerate

```powershell
cd asn-decoders
.\run-golden.ps1
```

One JVM per case (the legacy transformer has static config and its cartesian join can OOM);
output is deterministic — a re-run is byte-identical.

## Layout

- `<case>/<datafile>.records.jsonl` — one decoded record map per line, legacy key order.
- `<case>/<datafile>.rows.jsonl` — flattened transform rows (`{record, type, row}`), where
  a usable legacy tx config exists.
- `<case>/report.json` — the config tuple (grammar / root tag / skipLines / framing / tx)
  plus per-file counters: `records` (full file), `capturedRecords`, `emptyRecords`, `rows`,
  `errors`.
- `SUMMARY.json` — all case reports.

**Capture is capped at the first 100 records per file** (CCN/OCC records are ~25 KB each;
uncapped the corpus is ~350 MB). Whole files are still decoded, so `records`/`readerRecCount`
give full-file structural parity; content parity uses the captured head.

## Parity

`PARITY.md` + `<case>/parity.json` are generated by `ParityCheck` (asn-golden) and
compare the NEW stack against this corpus — see `asn-decoders/README.md` for the
current parity status and known deviations.

## Caveats

- `records.jsonl` values come from the legacy decoders with all their known bugs
  (REDESIGN.md §3 lists which are contractual and which are not).
- One skipped/empty record per OCC/CCN file (`emptyRecords: 1`) is legacy behaviour.
- Rows for aftel KABUL…543 differ between capped (738) and uncapped (1107) runs only
  because of the 100-record cap.
- Samples contain real subscriber identifiers (MSISDN/IMSI) — same exposure as the
  committed `data/` samples; treat the repo as sensitive, don't publish.
